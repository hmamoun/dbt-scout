# dbt_scout 🕵️‍♂️

**A tactical data warehouse utility package designed to audit warehouse hygiene, hunt down clutter, and scout out unmanaged data assets.**

As analytics environments grow, warehouses naturally collect "data debt"—tables and views left behind by deprecated models, ad-hoc queries, or structural changes. `dbt_scout` automatically scans your database metadata to surface infrastructure anomalies, ensuring your platform stays clean, secure, and cost-efficient.

[📦 View on dbt Hub](https://getdbt.com) | [🐙 GitHub Repository](https://github.com)

---

## 🎯 Key Features

*   **👻 Ghost & Orphan Object Detection:** Locates stale tables, views, and schemas inside your target database that are no longer managed or generated by your current dbt project.
*   **🧹 Warehouse Housekeeping Utilities:** (Coming Soon / Included) Essential macros to audit table storage footprints, track metadata size bloat, and streamline platform optimization.
*   **🔌 Cross-Database Native Support:** Engineered to run securely against metadata layers across multiple cloud data warehouses using warehouse-agnostic macro dispatching.

## 🚀 Quick Start

### 1. Installation
Add `dbt_scout` to your project's `packages.yml` file:

```yaml
packages:
  - package: your-github-username/dbt_scout
    version: 1.0.0
```

Run `dbt deps` to install the package.

### Sample Agent and Streamlit Deployments

See the [application materialization runbook](docs/materializations.md) for
working examples of `mat_scout_agt` and `mat_scout_stl`, the opt-in `scout_agent`
and `scout_streamlit` models, required Snowflake privileges, and test commands.
The runbook includes instructions for consuming this package locally from
`dbt_test`. Neither sample deploys during an ordinary build without its settings.

### Standalone Agent Comparison

The [one-page Agent Comparison workbench](docs/compare_agents.md) is distributed
under `streamlit/compare_agents`. It uses the existing Streamlit materialization
and does not require the original evaluation application or evaluation tables.
The guide covers consumer configuration, owner-rights access, dependencies,
least-privilege permission templates, Task validation, and deployment limitations.

### 2. Basic Usage
To run the primary scout macro and identify orphan objects in your warehouse, execute the following command in your terminal:

```bash
dbt run-operation find_orphan_objects
```
